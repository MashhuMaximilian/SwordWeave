# Character editing after creation

The new-character flow establishes identity, story, attributes, one optional mirrored weakness, and starting access. It should stay short. New and existing characters need the same deeper editing workspace on the character sheet.

## Next workflow

1. Open the character's build mode with its current pieces visible beside a searchable Library corpus. Keep the selected destination visible while browsing.
2. Let the player add multiple primitives, including verb tiers, ranges, output dice, domains, and later families. Show level eligibility, BU cost, remaining allowance, and mirror credit as each choice changes.
3. Offer optional seeded suggestions and a shuffle allowance, while allowing the player to keep and remove a small comparison list. Selecting a suggestion must never silently move or replace another item.
4. Before applying a piece, choose its destination: direct character access, Lineage, Upbringing, Manifest, an existing capability, or a new capability. Show a preview of the resulting hierarchy and BU totals.
5. Support moving existing pieces between those destinations without repurchasing them, and make direct pieces and bundled pieces visibly distinct.
6. Use the existing Build & Preview drawer for creating or forking definitions in context. A saved definition returns to the current character and destination without sending the player to Atelier.
7. On mobile, use explicit Corpus, Build, and Preview views with the chosen destination and draft selections preserved between views.

The current creation package is a starting foundation, not a permanent container. Players can add and organize further primitives after creation. The Atelier character modal remains a separate sandbox.
