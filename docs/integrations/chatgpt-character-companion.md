Started 2026-11-25 from local SwordWeave revision `6ef5b9c2f239f6f7383bf40d97699dd676562083` and the accompanying worktree changes. The [delivery roadmap](../implementation/chatgpt-companion-roadmap.md) owns the release sequence.

## Implemented locally

- `POST /api/mcp` serves stateless Streamable HTTP. The protected-resource URL is `/.well-known/oauth-protected-resource/api/mcp`. The MCP and discovery routes bypass website session middleware and perform their own OAuth credential checks.
- Configure the exact resource URL and Clerk authorization issuer in `MCP_RESOURCE_URL` and `MCP_CLERK_ISSUER`. HTTPS is required except for the local loopback resource. The transport is off by default. Configure the independent read and write flags only for the intended environment.
- The server verifies JWT OAuth tokens with the installed Clerk backend. It also checks the exact issuer and audience, expiry, subject and required tool scopes before translating a linked Clerk subject to an active SwordWeave account. The transport never uses website cookies as OAuth credentials.
- The fictional receipt fixture is a separate tool surface. It requires a Clerk development key, the isolated database name `sw_companion_test` on the explicitly configured host, and exactly two allowlisted internal user IDs. It records one per-user receipt in process memory. An out-of-fixture user can never create a receipt. Run staged fixture tests in one server process.
- The regular tool surface includes sourced Play Guide reads, bounded catalogue discovery and a character preview with an optional inline widget. Set `MCP_CURSOR_HMAC_SECRET` to a random server secret with at least 32 bytes for catalogue and paginated character reads. Catalogue results include exact pins where independently verified. The starting access review shows verb tier, domain, range and die type, and explains eligible free baselines and optional mirrored drawback credit.
- `MCP_STAGING_REVIEW_ENABLED=true` admits browser reviews only in the guarded fictional fixture. The linked actor can review and confirm a private character, a progression PDF or a separate append to Player Notes. Creation supports exact direct pins, eligible reused capabilities, private capabilities with pinned or newly authored primitive members, and private forks of supported primitives and capabilities. Capability reviews freeze member order, roles, quantities and pins. Newly authored dependencies commit first and supply verified native pins. Forks capture the authorized source version and refuse unchanged or unreproducible input. Each authored piece and the character have their own reviewed step and receipt. [Adapter boundaries](../implementation/chatgpt-companion-phase-1.md#creation-draft-and-version-selectors)
- A completed character save includes the standard sheet PDF link. The read-only `get_character_sheet_pdf_link` tool accepts native website print options for any owned or actively shared character. Its same-origin download requires a current Clerk browser session and rechecks access. The standard PDF shares the website projection, rendering and attachment behavior. The separately approved progression PDF uses its own one-hour document. Both use the application's Python and ReportLab runtime.
- Independent edit and play read switches expose scoped character context. Staged edit writes support foundation changes, exact attachment of eligible pinned primitives, effects, items, heritages and capabilities, and supported direct and nested proposal changes. Owners can review advancement or author and attach a private primitive or primitive-member capability from exact pins. Pending proposals expose a rollback-only diff to the owner or author while both retain access. `MCP_CHARACTER_VERSION_PROPOSAL_READS_ENABLED=true` adds an explicit staged version proposal subtype. The additional `MCP_CHARACTER_VERSION_PROPOSAL_WRITE_ENABLED=true` enables reviewed submissions and owner decisions for supported exact direct slots with the edit write scope. Staged play writes support Markdown notes, manual Vitality, owner consequences and a subset of source-pinned consequence packages. Real-data writes require server-verifiable ChatGPT approval and the roadmap's staging tests.

The Clerk administration MCP server is useful for configuring a development instance, while player consent uses Clerk OAuth through the SwordWeave resource server. ## ChatGPT data handling and publication

- ChatGPT sends tool arguments derived from the conversation to SwordWeave and receives the authorized results as chat context. Clerk handles sign-in and supplies the scoped tokens that bind calls to the linked account. The integration sends reviewed drafts, rules, and permitted sheet data for the task the player requests. A staged fixture call only reads or saves a fictional receipt.
- ChatGPT may use relevant chat context and enabled memories when invoking a connected app. OpenAI's response handling depends on the account's memory and data controls. An authorized write can persist on the SwordWeave sheet or in its operation receipts after disconnecting. Describe those effects and how to disconnect in the public notice before submission. [Connected apps and data controls](https://help.openai.com/en/articles/11487775-connected-apps-in-chatgpt)
